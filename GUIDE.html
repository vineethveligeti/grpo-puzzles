GRPO Puzzles

Two small reinforcement-learning projects, one machine. A base 0.8B model learns to solve the Countdown numbers game with no demonstrations; a 4B model is pointed at a word-ladder puzzle whose author showed naive RL makes things worse. This page is the picture version of the two GUIDE.md files.

98Countdown Qwen3.5-0.8B-Base · 490k puzzles · one evening F/BWordmaze Qwen3.5-4B · 2k puzzles · 1–2 weeks

The loop both projects run

GRPO has no critic and no learned reward model. For every prompt it samples a group of eight answers, a Python function scores each one, and the score is turned into an advantage by normalising inside the group. Tokens in above-average answers get pushed up, the rest down, with a PPO-style clip.

98 Countdown: what earns the reward

Two functions, logged separately by TRL so you can see the format get learned before the arithmetic does. The answer reward is your solve rate.

F/B Wordmaze: ten checks, and where the reward attaches

The verifier returns ten booleans. Most are free — every model passes them. Two are hard, and both are about letters, which a tokenizer hides. The reward is attached so that the known hack earns almost nothing and a real ladder earns something.

What the curves should look like

Schematic, not data. The three shapes to recognise, with the only published reference points for this task (Mini-R1: Qwen2.5-3B-Instruct, 8 generations, 4×H100). A 0.8B base will be slower and noisier — that difference is your result.

Five things about Qwen3.5 the tweet leaves out

It's a vision-language checkpoint.
architectures: ["Qwen3_5ForConditionalGeneration"]. Load with AutoModelForCausalLM → transformers gives you the text-only Qwen3_5ForCausalLM. Pass the model name to GRPOTrainer instead and TRL loads the full VLM with a processor — in float32.
18 of 24 layers are Gated DeltaNet.
Without pip install flash-linear-attention transformers silently falls back to a slow PyTorch path — and 5.16 prints no warning, so check: python -c "from fla.ops.gated_delta_rule import chunk_gated_delta_rule". The second kernel, causal-conv1d, is a width-4 depthwise conv; it falls back independently and cheaply, so skip it if its build fails (or use pip install kernels + use_kernels=True).
The vLLM fast path was broken for this exact setup until August.
TRL #5269 / vLLM #36275: no text-only Qwen3.5 class in vLLM, so weight sync failed. Fixed in vLLM 0.27.0 (merged 2026-07-29); TRL 1.12 accepts ≤ 0.27.1. Scripts default to use_vllm=False; add --use_vllm once the slow path works.
248,320-token vocabulary.
The logits tensor at the loss step — batch × completion length × vocab — is the memory hog, not the 0.8B of weights. Halve per_device_train_batch_size before reaching for LoRA.
<think> is a real token but not a "special" one.
So it survives TRL's skip_special_tokens=True decode and format rewards can see it. Base EOS is <|endoftext|>; the instruct template opens <think> by default and only pre-closes it with enable_thinking=False.

Order of work

  1. Countdown, baseline. eval_countdown.py --sample --k 8. Ten minutes. Decide the branch above.
  2. Countdown, train. One A100 evening. First five steps: step_time, fla import check passed, frac_reward_zero_std below 1.
  3. Countdown, after + write-up. Same 500 puzzles. Plot, 5 samples, ablation: 0.8B vs 2B on one chart. Thread; tag @TheGlobalMinima and @jiayi_pirate.
  4. Wordmaze, baseline table. 0.8B / 2B / 4B × plain / spaced, per-check rates. Already a figure the author doesn't have.
  5. Wordmaze, the hacking receipt. 100 steps with a deliberately naive reward, then 100 with the shaped one. Two curves, one figure — the most shareable artefact here.
  6. Wordmaze, train + generalise. Train on 4-letter/3-move, evaluate on 5×3 and 4×4. Skill or memorisation? Publish; offer the verifier as a PR to the dataset repo.

Compute is Colab Pro. Measure five steps before trusting any time estimate; the guides mark every estimate as such.
